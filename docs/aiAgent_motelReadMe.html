Agentic Booking System Documentation

This document describes the internal architecture, goals, context model, decision logic, and adaptive learning loop of the Agentic Motel Booking System. It is designed as an operator‑centric reference for developers, auditors, and system integrators.

1. System Overview

The Agentic Booking System is a self-contained decision-making loop that evaluates guest requests, interprets motel state, selects an optimal room type, proposes a price, and adapts its strategy based on guest acceptance or rejection.

AGENTIC LOOP (HIGH-LEVEL) ┌──────────┐ │ GOALS │ └────┬─────┘ │ ┌────▼─────┐ │ CONTEXT │ ← guest request + motel state └────┬─────┘ │ ┌────▼─────┐ │ DECISION │ ← scoring, pricing, feasibility └────┬─────┘ │ ┌────▼─────┐ │ ACTION │ ← offer room + price └────┬─────┘ │ ┌────▼─────┐ │ ADAPTIVE │ ← memory update │ LEARNING│ └──────────┘

2. System Goals

The agent pursues multiple goals simultaneously, balancing guest satisfaction with motel revenue and operational constraints.

Minimize guest friction
Respect capacity + availability
Optimize revenue
Honor guest preferences
Maintain operational safety

Goal Definition (Formal)

GOAL = argmax( guest_satisfaction + revenue_margin + operational_safety ) subject to: - capacity constraints - availability constraints - occupancy pressure - learned preference weights

3. Context Model

The agent constructs a structured context object from two sources:

3.1 Guest Request Context

Check-in date
Check-out date
Guest count
Room preference
Price sensitivity

3.2 Motel State Context

Room inventory
Occupancy pressure
Base prices
Capacity limits

Context Object (Example)

{ checkIn: "2026-04-07", checkOut: "2026-04-08", guests: 2, preference: "deluxe", priceSensitivity: "medium", motelState: { occupancyPressure: "high", roomsAvailable: { standard: 4, deluxe: 2, suite: 1 } } }

4. Decision Logic

The agent evaluates all feasible room types and assigns a score to each based on multiple weighted factors.

4.1 Feasibility Filter

Capacity ≥ guest count
Availability > 0

4.2 Scoring Model

Each feasible room type receives a composite score:

score(roomType) = learned_preference_weight + guest_preference_bonus + price_sensitivity_alignment + occupancy_pressure_adjustment + base_price_factor

4.3 Price Adjustment

Final price is adjusted dynamically:

High occupancy → price ↑
Low occupancy → price ↓
Price-sensitive guest → discount
Comfort-first guest → premium

4.4 Decision Output

{ chosenRoom: "Deluxe", offerPrice: 148, acceptanceProbability: 0.72 }

5. Action Phase

The agent presents the selected room and price to the guest. The guest response (accept/reject) is simulated or captured from real input.

If accepted → commit inventory
If rejected → treat as negative signal

6. Adaptation & Learning

After each booking attempt, the agent updates its internal preference weights.

Learning Rule

if accepted: preferenceScore[roomType] += +1.0 else: preferenceScore[roomType] += -0.7

Effect of Learning

Agent becomes better at matching guest behavior
Pricing becomes more accurate
Room selection becomes more aligned with demand
Poor-performing room types are deprioritized
