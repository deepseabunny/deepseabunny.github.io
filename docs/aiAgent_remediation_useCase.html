Autonomous Maintenance Agent

A single maintenance crew, watching a unified JSON data model for rooms that need remediation in a hotel / motel / apartment property.

The agent continuously inspects room states, creates maintenance tickets, and alerts the crew whenever a room reflects a needs maintenance status—no extra ceremony, full auditability.

1. JSON data model for rooms

Each room in the property is represented in a JSON structure. The agent treats this as the source of truth for operational state.

1.1 Example property JSON
{
  "propertyId": "PROP-001",
  "name": "Downtown Suites",
  "type": "HOTEL_MOTEL_APARTMENT",
  "rooms": [
    {
      "roomId": "210",
      "floor": 2,
      "type": "STUDIO",
      "status": "OCCUPIED",
      "maintenanceStatus": "NEEDS_MAINTENANCE",
      "flags": {
        "needsCleaning": false,
        "maintenanceIssue": true
      },
      "amenities": {
        "internet": { "wifiStatus": "UP" },
        "tv": { "tvStatus": "OUT_OF_SERVICE" },
        "phone": { "phoneStatus": "OPERATIONAL" }
      },
      "maintenance": {
        "activeTicketId": null,
        "history": []
      }
    }
  ],
  "maintenanceTickets": []
}

The key field for triggering the agent is maintenanceStatus (e.g. "NEEDS_MAINTENANCE"), plus any supporting flags or amenity states.

2. Detection logic for maintenance needs

The AI agent continuously scans the JSON model (or diffs between snapshots) to find rooms that require remediation. A room is considered in need of maintenance if any of the following conditions are true:

  • Primary status: maintenanceStatus === "NEEDS_MAINTENANCE"
  • Flags: flags.maintenanceIssue === true
  • Amenities: TV, phone, or internet marked as out of service
2.1 Conceptual detection function
function detectMaintenanceRooms(propertyJson) {
  return propertyJson.rooms.filter((room) => {
    const needsMaintenance =
      room.maintenanceStatus === "NEEDS_MAINTENANCE" ||
      room.flags?.maintenanceIssue === true ||
      room.amenities?.tv?.tvStatus === "OUT_OF_SERVICE" ||
      room.amenities?.phone?.phoneStatus === "OUT_OF_SERVICE" ||
      room.amenities?.internet?.wifiStatus === "DOWN";

    return needsMaintenance;
  });
}

This function returns a list of rooms that should generate or update maintenance tickets and trigger alerts to the crew.

3. Maintenance ticket model

When a room is detected as needing maintenance, the agent creates a maintenance ticket. All tickets are stored in a global registry and linked back to the room.

3.1 Ticket JSON schema
{
  "ticketId": "MT-20260326-001",
  "roomId": "210",
  "issueType": "TV_OUTAGE",
  "detectedAt": "2026-03-26T23:38:00Z",
  "priority": "MEDIUM",
  "status": "OPEN",
  "assignedTo": "CREW-1",
  "notes": []
}

Priority rules:

  • HIGH safety, leaks, electrical, HVAC failure
  • MEDIUM TV, phone, internet outage
  • LOW cosmetic issues, minor flags
3.2 Ticket creation logic (simplified)
function createTicketForRoom(room) {
  const issueType = deriveIssueType(room); // e.g. "TV_OUTAGE", "WIFI_DOWN"
  const priority = derivePriority(issueType);

  return {
    ticketId: `MT-${Date.now()}`,
    roomId: room.roomId,
    issueType,
    detectedAt: new Date().toISOString(),
    priority,
    status: "OPEN",
    assignedTo: "CREW-1",
    notes: []
  };
}

4. Alerting the single maintenance crew

The property has one maintenance crew. The agent’s job is to send clear, actionable alerts whenever a new ticket is created or an existing one changes state.

Possible channels:

  • Dashboard panel: a live list of open tickets
  • Push / SMS / chat: message to a crew device or channel
  • In‑app banner: visible inside an operator console
4.1 Alert payload example
{
  "alertType": "MAINTENANCE_REQUIRED",
  "roomId": "210",
  "issue": "TV is OUT_OF_SERVICE",
  "priority": "MEDIUM",
  "ticketId": "MT-20260326-001",
  "timestamp": "2026-03-26T23:38:00Z"
}
4.2 Pseudo alert dispatch
function dispatchAlert(ticket, room) {
  const alertPayload = {
    alertType: "MAINTENANCE_REQUIRED",
    roomId: room.roomId,
    issue: ticket.issueType,
    priority: ticket.priority,
    ticketId: ticket.ticketId,
    timestamp: ticket.detectedAt
  };

  // Example: send to a crew dashboard or messaging endpoint
  sendToCrewChannel(alertPayload);
}

5. Ticket and room lifecycle

The AI agent doesn’t just create tickets—it manages the full lifecycle and keeps the JSON model in sync with reality.

5.1 Ticket states
  • OPEN: issue detected
  • ACKNOWLEDGED: crew has seen the ticket
  • IN_PROGRESS: crew is working on the issue
  • RESOLVED: crew reports fix completed
  • VERIFIED: system confirms room is operational again
5.2 Lifecycle transitions (conceptual)
function resolveTicket(ticket, room, propertyJson) {
  ticket.status = "RESOLVED";
  ticket.resolvedAt = new Date().toISOString();

  // Update room state
  room.maintenanceStatus = "OK";
  room.flags.maintenanceIssue = false;
  if (room.amenities.tv.tvStatus === "OUT_OF_SERVICE") {
    room.amenities.tv.tvStatus = "OPERATIONAL";
  }

  // Link ticket to room history
  room.maintenance.activeTicketId = null;
  room.maintenance.history.push(ticket.ticketId);

  // Optionally: write an audit log entry
  appendAuditLog(propertyJson, {
    type: "MAINTENANCE_RESOLVED",
    roomId: room.roomId,
    ticketId: ticket.ticketId,
    timestamp: ticket.resolvedAt
  });
}

6. AI agent loop (high-level)

The AI maintenance agent runs in a loop (or reacts to events) and keeps the property model aligned with real‑world maintenance activity. 

function maintenanceAgentTick(propertyJson) {
  // 1. Detect rooms needing maintenance
  const roomsNeedingMaintenance = detectMaintenanceRooms(propertyJson);

  // 2. For each room, ensure a ticket exists and crew is alerted
  roomsNeedingMaintenance.forEach((room) => {
    if (!room.maintenance.activeTicketId) {
      const ticket = createTicketForRoom(room);
      propertyJson.maintenanceTickets.push(ticket);
      room.maintenance.activeTicketId = ticket.ticketId;
      dispatchAlert(ticket, room);
    }
  });

  // 3. Optionally, reconcile resolved tickets and verify room states
  reconcileResolvedTickets(propertyJson);
}

This loop can be triggered on a schedule, on every JSON update, or via a streaming event system—whatever best matches your operational environment.
