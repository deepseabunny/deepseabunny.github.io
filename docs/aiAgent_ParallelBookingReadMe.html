Parallel Multi‑Agent Motel Simulator

This README documents the architecture, goals, agent behaviors, shared state model, and learning loops of the Parallel Multi‑Agent Motel Simulator. All agents run continuously in parallel, reading and writing to a shared blackboard state while coordinating indirectly through signals, state changes, and learned preferences.

1. System Overview

The simulator models a motel as a living multi‑agent ecosystem. Each agent operates independently in its own loop, but all share a common world model:

Agents do not call each other directly. Instead, they observe, interpret, and modify shared state, producing emergent coordination.

2. Agent Roles & Goals

2.1 Booking Agent

Primary decision-maker

Evaluates guest requests, filters feasible rooms, scores options, proposes a price, and simulates acceptance. Learns which room types succeed.

2.2 Housekeeping Agent

Room readiness

Scans for dirty rooms, prioritizes cleaning, and updates room cleanliness. Ensures Booking Agent sees accurate readiness.

2.3 Pricing Agent

Dynamic pricing

Adjusts prices based on occupancy pressure, demand index, and recent booking outcomes. Learns elasticity per room type.

2.4 Forecasting Agent

Demand modeling

Estimates demand index and expected occupancy using occupancy signals and noise. Feeds Pricing Agent with demand pressure.

2.5 Maintenance Agent

Room safety

Randomly introduces or resolves maintenance issues. Blocks/unblocks rooms for Booking Agent.

3. Shared State Model (Blackboard)

All agents read/write to a single shared object. This is the coordination substrate.

4. Agent Loop Behaviors

4.1 Booking Agent Loop

sense → context → decide → act → learn
  • Reads guest request + room states
  • Filters feasible rooms (clean, available, no maintenance)
  • Scores rooms using preference, price sensitivity, occupancy pressure, and memory
  • Simulates acceptance probability
  • Updates booking preference memory

4.2 Housekeeping Agent Loop

  • Scans for dirty rooms
  • Selects a subset to clean
  • Marks them clean
  • Implicitly learns throughput

4.3 Pricing Agent Loop

  • Reads occupancy pressure + demand index
  • Adjusts prices dynamically
  • Uses last booking outcome to refine elasticity

4.4 Forecasting Agent Loop

  • Computes occupancy ratio
  • Updates demand index
  • Feeds Pricing Agent indirectly

4.5 Maintenance Agent Loop

  • Randomly flags/unflags maintenance issues
  • Blocks/unblocks rooms
  • Ensures Booking Agent respects safety

5. Learning & Adaptation

5.1 Booking Agent Memory

Learns which room types succeed
if accepted: bookingPreferenceScore[type] += +1.0 else: bookingPreferenceScore[type] += -0.7

5.2 Pricing Agent Elasticity

Learns price sensitivity
if accepted: elasticity[type] += +0.5 else: elasticity[type] += -0.4

Other agents adapt implicitly through state changes and loop timing.

6. Emergent Behavior

Because all agents run in parallel, the system exhibits emergent patterns:

  • High demand → Pricing Agent raises prices → Booking Agent shifts to cheaper rooms
  • Maintenance issues → Booking Agent avoids flagged rooms → Housekeeping reprioritizes
  • High occupancy → Forecasting Agent raises demand → Pricing Agent surges
  • Frequent rejections → Booking Agent learns to avoid certain room types

No agent is “in charge” — coordination emerges from shared state.
